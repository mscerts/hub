# Learn Content Watch

*Runbook of the Learn Content Watch. Repo-wide rules live in [AGENTS.md](../../AGENTS.md); the other monitors are listed in the [index](README.md).*

Daily check for NEW official Microsoft Learn content for the exams the hub covers, so an exam page does not stay stale after Microsoft publishes something. Two detectors share one tracker and one issue per run: (A) the free **practice assessment** of an exam, and (B) the official instructor-led **courses** and their learning paths. Not rendered on the site, not part of the build.

- **Workflow:** `.github/workflows/learn-content-watch.yml` — daily 09:20 UTC (a test keeps every monitor that pushes to `main` on its own start time, which is only a convenience because scheduled runs often start hours late; the three-try push retry of the commit step is the protection) + manual trigger with a `force_baseline` checkbox. Runs never cancel each other. Step order: check -> issue -> tracker commit -> failure issue. The issue comes BEFORE the commit on purpose: what an issue reports is also recorded in the tracker, so when the issue step fails the commit is skipped and the next run (or "Re-run failed jobs") reports the same items again; committing first would lose the alert. The commit retries its push three times (`git pull --rebase`). Issues are labelled `enhancement`, no assignee; a failed check is ONE `bug` issue titled `Learn Content Watch Failed` (a comment for every further failed run, closed by the first healthy run, through `scripts/failure-issue.mjs`).
- **Script and tests:** `scripts/learn-content-watch.mjs` (Node, no dependencies; `node scripts/learn-content-watch.mjs`) and `tests/scripts/learn-content-watch.test.mjs`, fully offline: pure functions on trimmed real Learn pages and catalog answers in `tests/fixtures/learn-content-watch/`, end-to-end runs against a local fake of Learn (catalog, uid lookups, certification and exam pages, practice routes, the AI Skills Navigator host), and the workflow contract including the commit step run against a scratch git remote.
- **Tracker:** `src/data_files/learn-content-watch.json` — `{ lastSynced, format, courses: [{ code, number, uid, title, paths: [{ uid, type, title }], firstSeen, lastSeen, lastChanged?, missingSince?, availableOn?, removedAt?, unlinkedReported? }], practiceAssessments: [{ code, state, detail?, kind?, assessmentId?, url?, candidateUrl?, routeLive, pageUrl, firstSeen, lastChanged, lastChecked, failedSince?, failureReported? }] }`, both lists sorted by code; `availableOn` is the announced availability date (`YYYY-MM-DD`) of a future-dated course ("This course will be available on 10/30/2026"), which the availability alert (4, below) compares with the next read; a catalog entry without summary text is no data and keeps the known date. It is rewritten only when something other than `lastSynced` / `lastSeen` / `lastChecked` changed (the comparison ignores the order of keys), so a quiet Learn never produces a commit. Write it only through the script.

## (A) Practice assessments
- **What is watched:** every non-draft exam page that LACKS the card, computed live with the rule of `scripts/audit-missing-resources.mjs` (a `LinkCard` title starting with `Microsoft Learn Practice Assessment`; the `(AI Skills Navigator)` variant counts, a stand-in such as `AZ-800: Microsoft Learn Practice Assessment` does not), never a hard-coded list. Microsoft usually publishes the assessment within about 8 weeks after general availability and its `assessmentId` cannot be guessed (see `AGENTS.md > URL Formats`). A record is dropped once the card exists.
- **Which Learn page:** the certification or exam page the hub page links in its `Exam <CODE>` card (fallback `/credentials/certifications/exams/<code>/`), requested at `learn.microsoft.com/en-us/...`. The state of an exam is `link` | `unavailable` | `unknown`:
  - `link`: classic page (the `practiceAssessmentUid` meta tag and a "Take the practice assessment" link), new layout (`data-practice-assessment-link-*` attributes, which name the exam), or an AI Skills Navigator callout that links the assessment there. An id counts only when it is digits and belongs to this exam (or the page is about this exam alone); a page that offers practice assessments without saying for which exam is `unknown` with detail `ambiguous`.
  - `unavailable`: the static sentence "Practice Assessment for this exam is not currently available" is shown.
  - `unknown`: neither (`no-mention`, `exam-not-listed`, `no-learn-page` for an exam without a Learn page yet, `ambiguous`, `link-not-resolving`, or `unreadable` for a page that never could be read). A guid `assessmentId` in a script block is Learn's feedback widget, not a practice assessment.
- **Verification before "available":** the address is built in the hub's form (no `/en-us/`, `&WT.mc_id=studentamb_165290` appended, and `practice-assessment-type=certification` only on a certification route: the exam route `/exams/<code>/practice/assessment` is written without it, `AGENTS.md > URL Formats`) and requested: HTTP 200 without a redirect to another page. The page's own route comes first (where Learn's own link points), then `/exams/<code>/practice/assessment`; the existing cards use both forms (checked 2026-10-14: AZ-104, GH-300, MB-230 and SC-401 use the certification route, AZ-900 and AB-100 the exam route, and the `practice-assessment-type=certification` parameter is missing on some cards) and both resolve when the route exists. Learn answers 200 to ANY assessment id on a practice route that exists (verified 2026-10-14: a made-up id on `azure-fundamentals/practice/assessment` still answers 200) and 404 on a route that does not, so the check proves the route, not the id: the id comes from the Learn page and the issue says to open the link once before adding the card. The AI Skills Navigator host answers 200 to every address; the issue says so.
- **Alerts:** `unavailable`/`unknown` -> `link` is "now available" with the exact `LinkCard` to paste. "Changed, check by hand" covers: the sentence is gone and no link took its place; a link that disappeared or changed; a link that does not resolve; an ambiguous page; and an early signal, the exam's `/exams/<code>/practice/assessment` route starting to answer 200 although the page shows no link (only trusted while a control exam code, `zz-000`, answers 404; it covers only exams whose assessment lives on the exam route, AZ-900 does, DP-700 and AB-730 do not). A stand-in card on the hub page is mentioned in the issue.
- **Unreadable pages:** a page that cannot be read (5xx, 403, timeout, a bot-check page) keeps the previous state with a warning, and an address that could not be verified concludes nothing. A page unreadable on `FAILURE_DAYS` (5) days in a row raises ONE "check by hand" alert (the watch for that exam is off), then stays quiet until a good read clears the marks (`failedSince`, `failureReported`).

## (B) Courses
- **Source:** `https://learn.microsoft.com/api/catalog/?type=courses&locale=en-us` (139 courses on 2026-10-14; fields `uid`, `course_number`, `title`, `summary`, `study_guide` = the learning path and module uids of the course, `exam` for 10 of them). A course maps to a hub exam by its number (`<CODE>T<nn>` with an optional `-A` suffix, e.g. `AB-650T00`, `MB-230T01`) or by its `exam` field; other numbers (`SC-5008`, bootcamps) map to nothing. Titles of added paths come from `.../api/catalog/?uid=<uids>`, 20 per request.
- **Alerts:** (1) a course exists for a hub exam and the exam page has no link under `/training/courses/<slug>` (once per course; `<slug>` is the end of the course address in the catalog `url`, else of its `uid`, else the lower-cased number: usually the number, but Learn drops a suffix such as `-A`, so AZ-104T00-A is served at `az-104t00`; the note says when the catalog announces a future availability date, "This course will be available on 10/30/2026" for AB-650T00); (2) the list of learning paths / modules of a tracked course changed (added and removed uids with titles, whether the hub page already links an added path, and which other tracked course already listed it); (3) a tracked course is missing from a healthy catalog on two UTC days in a row; (4) the announced availability date of a future-dated course moved, was withdrawn or newly appeared (the card description of `AB-650T00` on the exam page says "Becomes available October 30, 2026", so a moved date makes the page wrong; the alert says whether the page states the old and the new date). A bare `last_modified` move, a renamed course or a different order is never an alert. A catalog entry that loses its `study_guide` list keeps the paths that were known (warning).

## Rules, failsafes and first run
- **First run** (no tracker): everything already in place is recorded silently, EXCEPT the actionable state, which goes into the first issue: courses the hub pages do not link and practice assessments that are already published. Trigger the workflow once after it is on `main`; it commits the baseline.
- **A fetch failure is never evidence:** the previous state stays and a warning is logged (stderr, workflow annotation, job summary). One request at a time, `FETCH_DELAY_MS` (1000) apart, browser user agent, retries with a capped `Retry-After`; a run makes about 40 requests (about 75 seconds).
- **Failures (`extraction_failed`, a `bug` issue, nothing written):** the catalog is unreachable, not JSON, lists fewer than `MIN_COURSES` (100) courses, or its shape changed (no `courses`, fewer than 90% of entries with `uid` and `title`, fewer than half with a `study_guide` list); no exam page found in `DOCS_DIR`; a corrupt tracker (a malformed record, or a date field that is not `YYYY-MM-DD`: the dates are compared as text); more than `MAX_CHANGES` (15) alert items at once (a structure change on Learn or in the hub pages, not news). Real changes of that size: run the workflow with `force_baseline` ticked (or `FORCE_BASELINE=1` locally): they are recorded silently and the job summary lists what was swallowed.
- **Text from Learn** (course titles, path titles, reasons) is plain text in the issue: no HTML, links, code spans, `@mentions` or `#123` references; the report stays under 60,000 characters (rows shrink in steps).
- **Env overrides:** `LEARN_BASE_URL`, `ASN_BASE_URL`, `TRACKER_FILE`, `DOCS_DIR`, `REPORT_FILE`, `ERROR_FILE`, `GITHUB_OUTPUT`, `GITHUB_STEP_SUMMARY`, `MIN_COURSES`, `MAX_CHANGES`, `TITLE_BATCH`, `FAILURE_DAYS`, `FORCE_BASELINE`, `FETCH_DELAY_MS`, `FETCH_ATTEMPTS`, `RETRY_BASE_MS`, `MAX_RETRY_AFTER_MS`, `FETCH_TIMEOUT_MS`, `RUN_DEADLINE_MS`, `TODAY`. To try it without touching the committed tracker: `TRACKER_FILE=/tmp/lcw.json REPORT_FILE=/tmp/lcw-report.md GITHUB_OUTPUT=/tmp/lcw-out node scripts/learn-content-watch.mjs`. It writes the `GITHUB_OUTPUT` keys `changes_found`, `baseline_updated`, `extraction_failed`, `practice_alerts`, `course_alerts` and `issue_title`.
- **Known limits:** only exams whose page lacks the card are watched, so a card whose assessment later disappears from Learn is not noticed (verified 2026-10-14: the DP-800 Learn page shows no practice assessment although the hub links an AI Skills Navigator one); the watch sees the course and learning-path level, not new hands-on units inside an existing module (the lab pages still need the discovery steps under `AGENTS.md > Lab Page Workflow`); AZ-800, AZ-801 and GH-700 have no course in the catalog.

## Working the list
1. Open each Learn page or course page from the issue and verify it yourself (`AGENTS.md > Content Rules`): never infer an assessment id, a course number or a title.
2. Practice assessment available: open the link once, then add the card from the issue to the Tests tab of the exam page (use the "Microsoft Learn Practice Assessment" title, `(AI Skills Navigator)` suffix for that host, and decide about a stand-in card).
3. Course not linked: add a `Microsoft Learn` LinkCard (`https://learn.microsoft.com/training/courses/<slug>?WT.mc_id=studentamb_165290`, with the `<slug>` of the address the issue gives, which is not always the lower-cased course number) in the Text tab, after the other Microsoft resources of that grid; for a future-dated course put the verified availability date in the description.
4. Learning paths changed: check whether an added path belongs on the exam page (and, if it has exercises, on the lab page), and remove the card of a removed path. Course removed: look for the exam's new course number or remove the dead card.
5. Run `node scripts/audit-missing-resources.mjs`, commit the regenerated `src/data_files/missing-resources.json` with the page edits, then run `pnpm build`. Nothing needs to be dismissed: the tracker already records what the issue reported.
