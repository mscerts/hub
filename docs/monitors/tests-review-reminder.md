# Tests Review Reminder

*Runbook of the Tests Review Reminder. Repo-wide rules live in [AGENTS.md](../../AGENTS.md); the other monitors are listed in the [index](README.md).*

A ONE-TIME automation that raises ONE issue asking whether the unit tests of the monitors (`tests/fixtures/`, saved page samples that only those tests read, and every `tests/scripts/*.test.mjs` except the ones that do not test a monitor and stay (`KEPT_TESTS` in the script: `automation.test.mjs` for site code and `scripts/sitemap-check.sh`, `workflows.test.mjs` and `workflow-commit-steps.test.mjs` for all workflow files, `beta-pages.test.mjs` and `lib-beta-note.test.mjs` for the beta exam pages and their timeline notes)) can be removed. The tests matter only until every monitor has shown in production that it works, i.e. has raised a real alert at least once; they never run in production (only in the `pnpm test:scripts` step of CI on pull requests and locally). Not rendered on the site, not part of the build. It has no tracker and makes no commit: its state is GitHub itself (the issues and the workflow runs). It has no tests file on purpose (the point is less test code); it was proven with live dry runs and a fake `gh` instead (see "Trying it").

- **Workflow:** `.github/workflows/tests-review-reminder.yml` — runs Monday 11:20 UTC + manual trigger with a `dry_run` checkbox; permissions `issues: write`, `contents: read` and `actions: read` (the last one lets it count workflow runs); runs queue and never cancel each other; 10 minute timeout. It never pushes, so it is not one of the "workflows that push to `main`".
- **Script:** `scripts/tests-review-reminder.mjs` — Node, no dependencies; `node scripts/tests-review-reminder.mjs` (needs `gh` authenticated; a local run creates nothing without `CREATE_ISSUES=1`).
- **Rule:** the issue is raised when EVERY monitor in the script's `MONITORS` table has fired, or when `BACKSTOP_DATE` (default 2027-01-12, 90 days after the monitors landed) has passed (the UTC date of the run is after it). A monitor has *fired* when its workflow is on GitHub and at least one issue (open or closed) opened on or after `COUNT_FROM` (default 2026-10-14T22:41:29Z, when the reworked monitors were merged) has one of its ALERT titles; its failure issues do not count, and neither do the alerts of the code from before the rewrite (the old `Exam Retirement Notification`, `New MeasureUp Products Detected`, `Link Checker Report`, ...): they say nothing about the monitor as it runs now, so each monitor has to prove itself in its new form. A monitor whose workflow file is not on GitHub yet shows "not deployed" and counts as not fired.
- **One-time:** an issue titled exactly `Monitor tests: decide whether to remove them` in ANY state means "already raised": the run does one `gh issue list`, prints `already raised` and exits 0. Closing the issue without removing the tests is therefore fine and the reminder stays quiet. Label `enhancement`, no assignee.
- **The issue:** why it was raised (all monitors fired / the backstop date passed), the evidence table (monitor, workflow, first real alert as issue number and date or "not fired yet" or "not deployed", successful scheduled runs), what the tests are and are not, and a removal checklist: optionally archive `tests/` outside the repository; `git rm` of `tests/fixtures` and the monitor test files (the command is built from `tests/scripts` at run time; the kept test files listed above and `mcp-worker/tests` are not touched); `package.json` and the `pnpm test:scripts` step of `ci.yml` stay as they are while those files remain (only if `tests/` ends up empty: `test:scripts` removed, `test` runs only `test:mcp`, `'tests/**/*.mjs'` dropped from `format` and `format:check`, the CI step removed); the mentions in `AGENTS.md` and in the runbooks under `docs/`, with the `file > section` pairs found by a run-time grep of `AGENTS.md` and of every `.md` under `docs/`; delete this workflow, script and runbook (with its rows in `docs/monitors/README.md` and in the Monitors table of `AGENTS.md`); `pnpm build`, `pnpm format:check` and `pnpm test:scripts`. It says plainly that keeping the tests is a valid choice if the monitors will still be edited.
- **Every run:** prints the evidence table (and adds it to the job summary) and either `not raised: N of M monitors fired ...`, `already raised: #N ...` or the issue it raised, so the weekly run shows how far the monitors are.
- **On failure:** a failing `gh` call (or a malformed date) ends the run with an `::error` line and exit code 1: a red run, never a silent "not due".
- **Env:** `GITHUB_REPOSITORY` (default `mscerts/hub`), `BACKSTOP_DATE`, `COUNT_FROM` (YYYY-MM-DD or YYYY-MM-DDTHH:MM:SSZ), `TODAY` (YYYY-MM-DD), `CREATE_ISSUES` (the workflow sets it; the issue is only created with it and never with `DRY_RUN=1`), `DRY_RUN`, `AGENTS_FILE`, `DOCS_DIR` (default `docs`; every `.md` under it is scanned together with `AGENTS.md`), `REPORT_FILE` (the issue body when the issue is due), `GITHUB_STEP_SUMMARY`, `GH_TOKEN`, `GH_CLI_SCRIPT` (tests only: a fake `gh`), `FORCE_ALL_FIRED` (proof only: every monitor counts as fired; it refuses to run with `CREATE_ISSUES=1` unless `DRY_RUN=1`, so it can never create a real issue).
- **Adding or renaming a monitor:** add a row to `MONITORS` (name, workflow file, a pattern for its ALERT titles only) or change its pattern; a new monitor has to fire before the reminder is due, until the backstop date. Verify a pattern against `gh issue list --state all --json number,title`.

## Trying it
```bash
DRY_RUN=1 node scripts/tests-review-reminder.mjs                                              # the real evidence table
FORCE_ALL_FIRED=1 DRY_RUN=1 REPORT_FILE=/tmp/body.md node scripts/tests-review-reminder.mjs   # the issue it would raise
TODAY=2027-01-13 DRY_RUN=1 node scripts/tests-review-reminder.mjs                              # after the backstop date
```

## Working the issue
1. Decide: keep the tests (close the issue, nothing else) or remove them (follow the checklist in the issue; step 5 deletes this workflow, script and runbook).
2. Whatever the choice, nothing else needs to be done: the reminder is not raised twice.
