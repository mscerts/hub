# Course Videos Monitor

*Runbook of the Course Videos Monitor. Repo-wide rules live in [AGENTS.md](../../AGENTS.md); the other monitors are listed in the [index](README.md).*

Daily check of the recordings of Microsoft's instructor-led courses on YouTube (the `Microsoft Learn <CODE> Course on YouTube` cards of the Videos tabs), so a new course gets its card and the cards keep working. Not rendered on the site, not part of the build.

- **Workflow:** `.github/workflows/course-videos-monitor.yml` — runs daily at 05:40 UTC + manual trigger (`force_baseline` input, see "Failsafes"). The issue is opened BEFORE the baseline is committed (same order as the [MeasureUp Monitor](measureup.md)), so a failed issue step skips the commit and the next run reports the same changes again; the price is a possible duplicate issue when the commit fails after the issue was opened (the commit retries its push three times). Runs never cancel each other.
- **Script:** `scripts/course-videos-check.mjs` — Node, no dependencies; run with `node scripts/course-videos-check.mjs`. Tests, fully offline against a fake aka.ms, Learn catalog, Learn page and oEmbed endpoint, plus the workflow's step order and its commit step, in `tests/scripts/course-videos-check.test.mjs`; a trimmed real Learn page and catalog in `tests/fixtures/course-videos/`.
- **Baseline:** `src/data_files/course-videos.json` — `{ lastChecked, totalCourses, staleHubCards?, courses: { "<CODE>": { playlist, since, missed? } } }`. `courses` holds the codes whose short link resolves to a YouTube playlist (`playlist` is the YouTube playlist id, `since` the day the monitor first saw it; `missed: 1` marks a first "no longer resolves" answer waiting for confirmation). `staleHubCards` (`<file>|<href>` -> `{ problem, since }`) exists only while exam page cards are known to be wrong. `lastChecked` is the time of the last rewrite, not of the last run: the file is only rewritten when something changed, so a quiet day produces no commit.
- **On a new course video or a card to review:** ONE issue (`enhancement`) with a "New course videos" table (the Learn catalog title, the playlist title from YouTube, the hub exam page, the hub files that already link it, the short link), the card to add, an "Exam page cards to review" table (card, problem, `file:line`, suggestion), and informational tables for playlists that changed and courses that stopped resolving, then a checklist. A changed playlist or a course that stopped resolving never opens an issue on its own: the baseline is refreshed and the run logs it.
- **On failure:** ONE `bug` issue with the stable title `Course Videos Monitor Failed` (a comment for every further failed run, closed by the next healthy run, through `scripts/failure-issue.mjs`, see `AGENTS.md > CI/CD > GitHub Actions workflows`) with the reason, and nothing is written (`extraction_failed`).

## Why the short links
Microsoft gives every course a short link, `https://aka.ms/<CODE>onYouTube` (`AZ-104`, `SC-401`, and the four-digit courses such as `AI-3016` and `SC-5006`), that redirects to the course's playlist on the Microsoft Learn channel. It stays correct when Microsoft re-records the course or moves the playlist, and an unknown name redirects to a Bing page (`https://www.bing.com?ref=aka&shorturl=<name>`), which is how "this course has no recording yet" looks from outside. That is why the hub cards use the short link and the monitor asks aka.ms, one code at a time. The sources the monitor tried and why they are not the primary check (all read 2026-10-20):
- **The Learn page** `https://learn.microsoft.com/training/course-videos-on-shows` lists 47 of the 52 codes that resolve, and one of its links (`MS-4007`) does not resolve. It misses AB-100, AI-103, AI-300, AI-901, GH-100 and SC-401, so it is only a second opinion: its codes are asked too, and the job summary says how complete it is on every run.
- **The YouTube channel** cannot be read reliably without an API key: the channel's RSS feeds answer 404/500, and its "playlists" tab shows only the first twenty playlists with no working continuation. An `oembed` request (no key) does return a playlist's title, which is how the issue shows it.
- **The Learn catalog** (`https://learn.microsoft.com/api/catalog/?type=courses`) is the list of course numbers (`AZ-104T00`, `SC-5006`) that may have a recording, including the four-digit courses (`AI-3016`, `SC-5006`) whose code is not an exam code.

## How it works
1. Collects the course codes that could have a recording: the Learn catalog (`C-NNNT00` becomes `C-NNN`, `C-NNNN` stays), the codes of the Learn course videos page, the exam codes of the hub's own exam pages (a course that is not in the catalog yet), the codes of the short links the hub already uses, and the baseline.
2. Asks aka.ms for each code and a control code that cannot exist (`ZZ-0000`), one request at a time (0.3 s apart), without following the redirect: a redirect to a YouTube playlist is "resolves", a redirect anywhere else (Bing) or a 404 is "no recording", a redirect to YouTube that is not a playlist (a video, a channel) is logged in the job summary and not followed, and a 429, a 5xx, a timeout or a redirect without a place to go is "unverified": it proves nothing, so the code is kept as it was.
3. Compares with the baseline by SET of codes. A code that resolves and was not in the baseline is new. A code that resolves to another playlist than before is changed (the `since` day moves). A code that stops resolving is only marked `missed` on the first run and dropped when the next run says the same, because a short link that hiccups once must not be reported as a new course the next day.
4. Checks the hub's own cards: a card that links a playlist of a course directly where the short link resolves to the very same playlist (`use-short-link`), a card that links the playlist a code resolved to before but no longer does (`moved`), and a short link that does not resolve (`broken`, only for a code that never resolved or was confirmed gone). The code of a direct playlist link comes from the playlists the monitor knows; the title of the card (`Microsoft Learn <CODE> Course on YouTube`, or `<CODE>: Microsoft Learn Course on YouTube`) is the fallback for a playlist it has never seen. A creator's playlist (`John Savill`, `AGuideToCloud`) matches neither and is ignored. Findings are remembered in `staleHubCards`, so a card is reported once; a fixed card drops out by itself.
5. For new and changed playlists only, reads the playlist title from `https://www.youtube.com/oembed` (a courtesy for the issue: a title that does not start with the code is a warning annotation, because it usually means the wrong playlist).
6. For a new course whose code is not an exam with a hub page (`AI-3026`, `SC-5006`; `AZ-401` is its own placement), suggests the exam pages it could go on, with the evidence, in the "Suggested exam pages" column of the issue. The matching is the [course placement](../course-placement.md) tool (the course's modules against the exams' official courses, its words against the study guides, the skill groups it covers); it needs the learnsync data (about 7 MB from GitHub `main`) and the stored guides, and when it cannot read them the issue is written without it, with a warning annotation. `PLACEMENT=0` switches it off. `node scripts/course-placement.mjs --unplaced` lists the courses that have a recording and no card yet, with suggestions.
7. The first run (no baseline) and `force_baseline` record everything silently.

## Failsafes
Each stops the run with `extraction_failed` (a `bug` issue) and leaves the baseline and the report untouched; every threshold has an env override listed in the script header.
- The Learn catalog is unreachable, not JSON, has no `courses` list, or lists fewer than `MIN_CATALOG` (50) course codes. The Learn course videos page is a second opinion: when it cannot be read, or shows fewer than `MIN_PAGE_CODES` (10) short links, the run goes on and a warning annotation says so.
- The control code resolves to a YouTube playlist (aka.ms would "find" every course), or more than `MAX_UNVERIFIED_PCT` (20%) of the requests failed (aka.ms unreachable or blocking).
- More than `MAX_NEW_PCT` (50%) of the baseline new at once, or more than `MAX_GONE_PCT` (50%) of it not resolving at once: the short link scheme or the course codes changed, not news. If the change is real, run the workflow with `force_baseline` ticked (or `FORCE_BASELINE=1 node scripts/course-videos-check.mjs` locally and commit the baseline): everything is accepted silently, so look at the job summary for what was swallowed.
- Corrupt baseline (invalid JSON, no `courses` object, an entry without a valid playlist id). A fetch failure is never evidence: retries wait as long as the server's `Retry-After` says (up to `MAX_RETRY_AFTER_MS`, 60 s) and otherwise back off exponentially from `RETRY_BASE_MS` (5 s).

## Working the list
1. New course video: open the short link in the table and check that the playlist is the course's own (the title starts with the code). Add the card to the Videos tab of the hub exam page named in the table, next to the other instructor-led training cards: `<LinkCard title="Microsoft Learn <CODE> Course on YouTube" href="https://aka.ms/<CODE>onYouTube" target="_blank"/>`, with a short `description` (the course title) when it helps. A four-digit course (`AI-3016`) belongs on the page of the exam whose study guide covers it (AI-103 has `AI-3016` and `AI-3026`, SC-500 has `SC-5006`); a predecessor's course keeps its code in the title (`AZ-400: Microsoft Learn AZ-2008 Course on YouTube`). A code with no hub exam page needs nothing until that page exists.
2. Card to review: change the `href` to the suggested short link. For a short link that does not resolve, find the current playlist on the Microsoft Learn channel and decide whether the card stays (it may be a course whose recording was removed).
3. Run `node scripts/audit-missing-resources.mjs` if a card was added, then `pnpm build`. Nothing needs to be dismissed: the baseline already records what was reported.

## Running locally
```bash
node scripts/course-videos-check.mjs                    # reads the live sites and may rewrite the baseline
BASELINE_FILE=/tmp/baseline.json REPORT_FILE=/tmp/report.md ERROR_FILE=/tmp/error.md GITHUB_OUTPUT=/tmp/out node scripts/course-videos-check.mjs   # try it without touching the committed baseline
```
A run makes about 110 requests (the catalog, the Learn page, one aka.ms request for every code, a title per new playlist) and takes about a minute. The baseline was seeded on 2026-10-20 with 52 courses; the same day the 26 cards that linked a playlist directly were moved to the short link.
